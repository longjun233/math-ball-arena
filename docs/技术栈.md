## 3. 前端技术栈

### 3.1 零构建链

**没有** npm 依赖、package.json、webpack、vite。浏览器直接执行源码：

```html
<script type="module" src="js/main.js"></script>
```

### 3.2 模块结构（10 个 ES Module，1139 行）

```
static/
├── index.html                   单页，语义化 DOM
├── css/style.css                深色科技风，CSS 变量 + flexbox + 渐变 + backdrop-filter
└── js/
    ├── main.js        入口：装配数据/物理/渲染/UI，驱动主循环与状态机
    ├── config.js      物理常量、球种定义、血量表达式兜底配置
    ├── api.js         fetch 封装（AbortController 3s 超时）+ 断网回退
    ├── formula.js     BigInt 阶乘、表达式解析、科学计数法格式化、启动自检
    ├── physics.js     固定步长积分、碰撞检测（纯函数，Node 可直接 import）
    ├── traits.js      球种特性钩子（重力球预留接口）
    ├── levels.js      关卡推进状态机
    ├── render.js      Canvas 2D 绘制（背景/尖刺/屏障/小球/安全区）
    ├── fx.js          粒子、伤害飘字、震屏、屏障碎片
    └── ui.js          DOM 界面（HUD、选球卡片、结算面板、调试面板）
```

### 3.3 用到的浏览器 API

| API | 用途 |
|---|---|
| **Canvas 2D** | 全部游戏画面。`roundRect` 路径、线性/径向渐变、`shadowBlur` 光晕、`clip` 血条裁剪、`measureText` + `strokeText` 文字排版 |
| **requestAnimationFrame** | 主循环驱动 |
| **BigInt** | 任意精度整数（`10^300` 血量、`170!` 伤害） |
| **ES Module** | `import` / `export`，零打包 |
| **fetch + AbortController** | 拉关卡配置，超时 3s 自动降级到内置配置 |
| **URLSearchParams** | `?debug=1` 开关调试面板 |
| **devicePixelRatio** | 高清屏 canvas 缩放（上限 2x） |
| **DOM API** | HUD、选球卡片、结算面板（非全 Canvas） |

### 3.4 为什么不用框架

| 理由 | 说明 |
|---|---|
| 游戏逻辑全在 Canvas | 不需要虚拟 DOM，React 在这没有收益 |
| 省掉整条构建链 | `mvn spring-boot:run` 一条命令跑全栈，不用 `npm install` |
| 调试直接 | 改 JS 刷新即生效（`application.yml` 里配了 `file:` 静态路径，开发时不用重启） |
| 体积 | 10 个模块共 1139 行，框架反而是负担 |

## 4. 数值与算法（本项目的技术核心）

| 问题 | 解决方案 | 实现位置 |
|---|---|---|
| 阶乘爆炸（`21!` 已超 `long`） | 后端 `BigInteger` + 阶乘缓存；前端 `BigInt` | `Formulas.java` / `formula.js` |
| `10^300` 无法用 JSON number | 血量以**十进制字符串**传输，前端 `BigInt` 解析 | `LevelDto.barrierHp` |
| 配置要可读可改 | **表达式解析器**：`"1e300"` / `"9.158e21"` / `"50"` → `BigInteger` | `LevelService.parseBarrierValue` / `parseBigIntExpr` |
| 物理在不同刷新率下一致 | **固定步长积分**：`Δt = 1/120s` 累加器，`dt` 钳制 ≤100ms，单帧最多 600 子步 | `main.js` / `physics.js` |
| 弹性"固定" | 撞击后 `vy = -v0` 恒定（**不是**衰减系数），`vx` 在 [40,160] 内随机 → 垂直与水平运动解耦 | `physics.js` |
| 碰撞检测 | 圆–矩形 AABB（屏障全宽），仅 `vy > 0` 且离开表面后重新武装，`hitCooldown = 0.06s` | `physics.js` |
| 尖刺速度怎么定 | **二分搜索临界速度**（36 次迭代）+ 真实物理逐帧模拟，不用解析公式 | `tools/calibrate.mjs` |
| 血量曲线怎么定 | 对数空间**幂律插值**（`CURVE_POWER = 2.2`），生成 27 道全局严格递增的指数 | `tools/design-levels.mjs` |
| 超大数字怎么显示 | `<10⁶` 千分位；`≥10⁶` 科学计数法（3 位有效数字 + Unicode 上标） | `formatDamage` / `formatHp` |
| 血条不能用浮点 | `(hp × 10000n) / maxHp` 全程 BigInt，求万分比 | `hpPercent` |

### 4.1 为什么必须"真机模拟"而不是解析估算

尖刺的触发点是「**小球在屏障 1 上弹跳到最高点时的球顶**」，不是「尖刺走满画布」；而且小球会随关卡推进下落到更低的屏障，可用时间随之变长。

早期版本用"均匀行程 700px"近似，结果第 6、7、9 关的判定全部算错。现在 `tools/calibrate.mjs` 直接 `import` 前端的 `physics.js` 做逐帧模拟 —— **标定用的物理内核和浏览器里跑的是同一份代码**，所以模拟结果 = 实机结果（实测 50.86s vs 预测 50.9s，误差 0.08%）。

## 9. 刻意没用的技术（及理由）

| 没用 | 理由 |
|---|---|
| 前端框架（React / Vue） | Canvas 游戏不需要虚拟 DOM，省掉整条构建链 |
| TypeScript | `BigInt` 在 TS 目标兼容性上反而添麻烦，纯 JS + JSDoc 足够 |
| 数据库 / JPA / MyBatis | 战报只需内存存储，重启即清（`RunService`） |
| Lombok | 14 个类，手写 getter 更可控，少一个注解处理器 |
| WebSocket | 游戏全在客户端算，后端只下发静态配置 |
| 外部 CDN / 字体文件 | 只用系统字体回退（`JetBrains Mono` → `Consolas`），断网不影响 |
| 前端打包工具 | 见 §3.4 |
| 缓存中间件 | 关卡配置在启动时算一次，无需 Redis |

## 10. 技术约束与已知限制

| 项 | 说明 |
|---|---|
| **改血量 / 物理参数必须重跑标定** | 阶数跨关累加，任何一关的血量改动都会改变球的成长速度，进而改变全局。流程：改配置 → `node tools/calibrate.mjs` → 抄回 `spikeSpeed` → `node tools/physics-selftest.mjs` |
| **当前关卡分界窗口较窄** | 第 6 关临界 18.5 px/s、第 7 关临界 15.0 px/s，取统一 16.5 px/s。若想让"阶乘球止步第 7 关"更稳健，可把第 7 关第一道从 `1e60` 抬到 `1e70` 左右拓宽窗口 |
| **重力球未启用** | `traits.js` 里预留了 `gravity` 钩子，但改变 `g` 会让所有弹跳参数失效，启用前必须重跑标定 |
| **战报仅内存存储** | 重启即清空。要持久化需引入 H2/MySQL |
| **不处理多用户并发** | 单机演示性质，无会话/房间概念 |
| **未做移动端触控适配** | 纯自动演示，无操作输入，仅需响应式缩放 |
