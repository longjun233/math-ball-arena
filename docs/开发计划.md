## 一、优化后的提示词（可直接复用）

> **任务**：用 Java + Spring Boot 做后端、HTML5 + Canvas 做前端，开发一款名为「数学弹球闯关」的自动演示数学小游戏，全程 Git 管理版本。玩家全程不操作，只在开局选一种「公式球」。
>
> **画面与元素**
> 1. 画布顶部有一整排横跨全宽的尖刺（锯齿墙），从屏幕上方以**恒定速度**匀速下落，作为可视化的时间限制。
> 2. 游戏主体是一颗小球，画布左右两侧为实体墙（撞墙水平反弹）。
> 3. 每关有 **3 道**水平屏障，屏障下方是底部安全区。
>
> **小球机制**
> 4. 小球绑定一个数学公式（如阶乘球 `n!`）。**常态下小球只显示公式本身（如 `12!`），不显示算出来的数值。**
> 5. 每次与屏障碰撞，公式阶数按**该球种固定的升阶步长**增加。步长在开局选球时就已确定，全程恒定、玩家不可调整、不随关卡变化（例如阶乘球恒为每击 +2）。
> 6. 碰撞瞬间才显示"当前伤害"：**伤害 = 升阶后公式的运算结果**，以飘字形式从屏障上浮出并淡出；伤害达到阈值后改用科学计数法显示。
> 7. 碰撞弹性固定：**反弹后的垂直分速度恒定、水平分速度在设定范围内随机**。因此弹跳高度与弹跳周期完全固定，只有左右落点随机。
>
> **屏障机制**
> 8. 每道屏障在屏障条上直接显示数字血量。
> 9. 每关三道屏障的血量是**固定绝对值**（10 的整数次幂，如 `10^38`），同关内指数级递增；血量与玩家选哪种球无关。
> 10. 屏障被撞击后扣除对应伤害；血量 **≤ 0** 时屏障破碎消失。允许被单次巨额伤害一击打穿 —— 对正方阶乘球这类增长恐怖的公式，每道屏障一击即破是合理且需要的观感。
> 11. 屏障破碎后小球穿过缺口落到下一道屏障；穿过第 3 道后落入底部安全区即通关该关。
> 12. 不同公式球面对同一道屏障所需碰撞次数天然不同，**不做统一量化**。
>
> **关卡与胜负**
> 13. 共 **9 关**。第 9 关第 3 道屏障血量锁定为 **10^300**。
> 14. 阶乘球是最弱的球种：可通关第 1~7 关，但**无论怎样都过不了第 8、9 关**（不是靠数值巧合，而是靠"限时内物理上撞不够次数"）。更强的球种（三角阶乘球、正方阶乘球等）才能突破后续关卡。
> 15. 通关一关**不弹结算界面**：只播 0.6 秒的关卡号过场，小球回到最上方重新下落。9 关全部通过才显示通关界面。
> 16. 尖刺触及小球立即结束，显示失败界面。
> 17. 结束界面（通关 / 失败）**只显示数据，没有任何按钮**；点击空白处直接返回主界面（选球界面）。
> 18. 单局总时长应落在 **0~2 分钟**区间。
> 19. 小球的重力与下落速度必须做成可配置项，为后续「重力球」（每次碰撞后下落速度增长）预留接口。
> 20. UI 由开发者自主设计，深色科技风，需有撞击 / 破碎 / 升阶的视觉反馈。
>
> **技术**
> 21. 关卡配置（血量、尖刺速度）由 Spring Boot 后端下发，改配置不改代码即可调难度；前端断网时使用内置兜底配置。
> 22. 公式球种类会不断扩充，关卡血量设计不得依赖某个具体球种的增长率。

## 二、玩法与流程

### 2.1 核心循环

```
选球 → 第1关 → (破碎3道屏障) → 第2关 → … → 第9关 → 通关界面
                  ↓尖刺触球
               失败界面
```

玩家唯一的决策在开局：选哪种公式球。之后是完全自动的数值竞赛 —— **球的伤害增长速度 vs 尖刺的下降速度**。

### 2.2 状态机

| 状态 | 说明 | 出口 |
|---|---|---|
| `HOME` | 主界面：公式球卡片列表 | 点击卡片 → `LEVEL_INTRO(1)` |
| `LEVEL_INTRO` | 0.6s 关卡过场（只显示 `LEVEL n`，无数据无按钮） | 自动 → `RUNNING` |
| `RUNNING` | 物理推进、尖刺下落 | 入安全区 → `NEXT_LEVEL`；触球 → `GAME_OVER` |
| `NEXT_LEVEL` | 第 n<9 关：小球瞬移回顶部 → `LEVEL_INTRO(n+1)` | 自动 |
| `ALL_CLEAR` | 9 关全过，通关界面（纯数据） | 点击空白 → `HOME` |
| `GAME_OVER` | 失败界面（纯数据） | 点击空白 → `HOME` |

> **关于"无通关界面"**：`NEXT_LEVEL` 不是结算界面，它是一个 **0.6 秒的过场动画**（画面闪白 → 关卡号闪现 → 小球已在顶部就位重新下落），全程无数据面板、无按钮。已确认保留；时长与开关做成配置项（`levelTransition: { enabled: true, durationMs: 600 }`）。

## 三、公式球族

### 3.1 步长是球种的固有属性

**升阶步长写在球种定义里，开局选球即确定，全程恒定，不随关卡改变，玩家也无法调整。**

| 代号 | 名称 | 公式 `f(n)` | 固定步长 | 定位 |
|---|---|---|---|---|
| `FACTORIAL` | 阶乘球 | `n!` | **每击 +2** | 最弱球种，天花板第 7 关 |
| `TRI` | 三角阶乘球 | `T(n)!`，`T(n)=n(n+1)/2` | **每击 +1** | 突破第 8 关 |
| `SQR` | 正方阶乘球 | `(n²)!` | **每击 +1** | 突破第 9 关 |

同阶数下的强弱关系：`n! < T(n)! < (n²)!`。同样从 `n=2` 起步，正方阶乘球第一次碰撞（`n=3`，`9! = 362 880`）的伤害就是阶乘球第一次碰撞（`n=4`，`4! = 24`）的 1.5 万倍。

### 3.2 扩展位（只留接口，v1 不实现）

| 代号 | 公式 | 说明 |
|---|---|---|
| `SUPER_FACTORIAL` | `sf(n)=∏_{k≤n} k!` | 超阶乘球，增长率介于 `n!` 与 `T(n)!` 之间 |
| `SUB_FACTORIAL` | `!n`（错排数） | 趣味球，增长率低于阶乘 |
| `POWER_TOWER` | `n↑↑2 = n^n` | 幂塔球，无尽模式 |
| `ITER_TOWER` | `n↑↑3` | 迭代幂塔，无尽模式 |
| `GRAVITY` | `n!` + 碰撞加速 | **重力球**：每次碰撞后重力/下落速度提升 |

球种通过 `BallFormula` 枚举 + `f(n)` 策略 + `step` 字段实现。**新增球种 = 加一个枚举值 + 一条公式 + 一个步长**，不改游戏逻辑、不改关卡血量。

### 3.3 为什么血量不能跟着球种走

关卡血量是**固定绝对值**，与玩家选什么球无关。这带来三个必要性质：

1. **可无限扩充球种**：新球种的强弱由它自己的公式决定，不需要为它重调 9 关数值；
2. **门槛是自然涌现的**：阶乘球打不过第 8 关，不是因为我们调了数值卡它，而是因为它在 7 秒内物理上撞不出足够的伤害；
3. **数值美观**：全部是 10 的整数次幂，界面显示为 `10^38`、`10^300`，玩家一眼就能读懂量级。

### 4.5 数值精度

- `21!` 已超出 `long` 上限；血量最高到 `10^300`（301 位十进制），球最终阶数到 `168!` 量级。
- **后端**：一律 `java.math.BigInteger`。
- **前端**：`BigInt` 负责扣血与判定，`Number` 只用于动画插值。
- **一致性自检**：后端在关卡配置里附带前 8 次撞击的伤害与累积校验值，前端启动时比对，不一致立即告警。

## 五、物理模型

### 5.1 参数（全部集中在可配置对象中）

| 参数 | 符号 | 取值 | 说明 |
|---|---|---|---|
| 逻辑画布 | W×H | 900 × 760 | 前端等比缩放适配窗口 |
| 重力加速度 | `g` | 2400 px/s² | **可配置**（重力球用） |
| 反弹垂直速度 | `v0` | 420 px/s | **固定**，决定弹跳高度与节奏 |
| 反弹水平速度 | `vx` | 40 ~ 160 px/s 随机 | **方向随机**，决定左右落点 |
| 弹跳高度 | `h = v0²/2g` | 36.75 px | 恒定 |
| 弹跳周期 | `T = 2v0/g` | 0.35 s | 恒定，与水平随机无关 |
| 屏障间距 | `d` | 110 px | 约束 `h < 0.6d` |
| 屏障厚度 / 球半径 | `t` / `r` | 16 px / 16 px | |
| 屏障位置 | — | y = 390 / 500 / 610 | 全宽，紧贴左右墙 |
| 底部安全区 | — | y > 670 | |
| 尖刺高度 / 行程 | `hs` / — | 60 px / 700 px | 从 y=0 落到 y=700 |

### 5.2 为什么是"垂直分量固定 + 水平分量随机"

你要求的"反弹方向在一定范围内随机，但弹跳高度固定"，在物理上精确对应：

```
撞击瞬间：
  vy = -v0                                  // 固定向上，保证弹跳高度恒定
  vx = randomSign() × uniform(40, 160)      // 方向与大小随机
```

由此得到三个关键性质：

- 弹跳高度恒定 → 小球永远不会飞过上一道屏障，也永远不会粘在屏障上；
- **弹跳周期恒定 → 通关耗时可以被精确预测**，这正是第四章那张限时表能算准的前提；
- 左右落点随机 → 画面不再是机械的上下直跳。

如果反过来做"速度大小固定、角度真随机"，垂直分量会随角度波动，弹跳高度与周期都不再固定，第四章整套限时数值全部作废。所以**必须固定垂直分量**。

### 5.3 边界与判定

- **左右墙**：实体墙，`vx = -vx`（无能量损失），垂直分量不受影响。小球永远不会横向飞出场外，也永远不会从屏障侧边漏下去（屏障全宽贴墙）。
- **球 vs 屏障**：圆–矩形相交，且 `vy > 0`（正在下落）时才判定撞击；撞击后做位置修正。
- **重复撞击保护**：`hitCooldown = 0.06s`，且必须离开屏障表面后才重新武装。
- **球 vs 尖刺**：尖刺锯齿底边 `y_spikeBottom ≥ ball.y - r` → 失败。
- **通关判定**：`ball.y - r > 670`。
- **固定步长积分**：`requestAnimationFrame` 取 `dt` 并钳制 `≤100ms`，用累加器以 `1/120s` 固定步推进，保证 60Hz / 144Hz / 掉帧下行为完全一致。
- **切后台**：`visibilitychange` 暂停，恢复时重置时间基准。

### 5.4 为"重力球"预留的接口

```js
// config.js —— 所有物理量都可被关卡配置覆盖
const PHYSICS_DEFAULTS = { gravity: 2400, bounceSpeed: 420, vxMin: 40, vxMax: 160 };

// traits.js —— 碰撞钩子，v1 全部为空实现
const TRAITS = {
  none:    { onHit: null },
  gravity: { onHit: (ball) => { ball.gravityMul *= 1.06; } },  // 重力球（预留）
};
```

⚠️ **重要约束**：重力球会改变 `g`，进而改变弹跳高度与周期，第四章整套数值将全部失效。启用任何改变 `g` 或 `v0` 的球种时，**必须先重跑 [balance-calc.mjs](<C:\dsh  GZQ\math-ball-arena\tools\balance-calc.mjs>) 重新校准 9 关的限时与尖刺速度**。这条写进 README。

## 六、UI 设计

### 6.1 数值显示规则（本次重点调整）

| 位置 | 显示内容 | 示例 |
|---|---|---|
| 小球**常态** | **只显示公式，不显示数值** | `34!` |
| 小球**升阶瞬间** | 公式跳变 + 放大 1.15 倍 + 白色闪光环 | `32!` → `34!`（台阶乘 2） |

| 血条 | 按「当前血量 / 初始血量」比例绘制（不用绝对值） | — |

**伤害飘字的格式阈值**：

```
damage <  1 000            → 原样         例：720
damage <  1 000 000        → 千分位       例：362,880
damage ≥  1 000 000        → 科学计数法   例：4.79×10⁸
```

升阶步长也要在 HUD 上常驻显示（`阶乘球 · 每击 +2 阶`），否则玩家看到 `22!` 跳到 `24!` 会以为算错了。

## 十、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 阶乘溢出 `long` | 血量到 `10^300`，`long` 早崩 | 全链路 `BigInteger` / `BigInt`；单测覆盖 `169!` 与 `10^300` |
| 随机角度破坏节奏 | 若按"速度大小固定、角度随机"，垂直分量波动，整套限时数值作废 | **固定垂直分量、随机水平分量**（见 5.2），从物理上杜绝 |
| 小球横向出界 / 从屏障侧边漏下 | 关卡逻辑崩坏 | 左右实体墙 + 屏障全宽贴墙 |
| 弹性衰减导致小球粘在屏障上 | 死局 | 固定反弹速度，不用衰减系数；加最小反弹速度断言 |
| 弹跳高度 > 屏障间距 | 小球撞到上一道屏障 | 构建期断言 `v0²/2g < 0.6 × 屏障间距` |
| 刷新率导致物理不一致 | 144Hz 与 60Hz 结果不同，门槛失效 | 累加器 + `1/120s` 固定步长；`dt` 钳制 ≤100ms |
| 解析耗时与实测偏差 | 余量卡不准 | 调试面板实测校准（M6 强制项）；每关余量断言 k ≥ 1.15 |
| 新增球种破坏平衡 | 加一个球就要重调 9 关 | 血量是固定绝对值，与球种解耦；新球只需定义公式与步长 |
| 重力球改动 `g` | 全部关卡数值失效 | 预留接口但不启用；README 写明启用前必须重跑 `balance-calc.mjs` |
| 超大数字撑破布局 | 血条与卡片错乱 | 血量用 `10^n` 表示 + 血条按比例绘制 + 伤害按 6.1 阈值切科学计数法 |
| 前后端公式漂移 | 显示与实际扣血不符 | 后端下发伤害序列校验值，前端启动自检告警 |
| 破碎瞬间重复撞击 | 一次撞击扣两次血 | 速度方向判定 + 冷却 + 离开表面后重新武装 |
| 切后台导致尖刺瞬移穿球 | 误判失败 | `visibilitychange` 暂停 + 恢复时重置时间基准 |

## 十一、验收清单（Definition of Done）

- [ ] 顶部整排尖刺匀速下落，速度与关卡配置一致，触球立即结束。
- [ ] 小球常态**只显示公式**（如 `34!`），不显示算出来的数值。
- [ ] 碰撞后才显示当前伤害飘字；伤害 < 10⁶ 用千分位、≥ 10⁶ 用科学计数法。
- [ ] 升阶步长是该球种的固有属性，开局确定、全程恒定、玩家不可调、不随关卡变化。
- [ ] **反弹方向随机、弹跳高度与弹跳周期完全固定**；小球不飞出顶部、不粘屏障、不横向出界。
- [ ] 每关恰好 3 道屏障，屏障显示 `10^n` 形式的血量，同关血量指数级递增。
- [ ] 屏障血量 ≤ 0 时破碎消失，小球穿过缺口落到下一道；穿过第 3 道进入安全区即通关。
- [ ] 9 关全部可跑；**通关一关不弹结算界面**，只播 0.6s 关卡号过场后小球回到顶部重新下落。
- [ ] 第 9 关第 3 道屏障血量为 **10³⁰⁰**。
- [ ] 阶乘球可通关第 1~7 关、在第 8、9 关必败；三角阶乘球可过第 8 关、过不了第 9 关；正方阶乘球可通关第 9 关。
- [ ] 9 关全过显示通关界面；尖刺触球显示失败界面；**两者均无任何按钮**，点击空白处返回主界面。
- [ ] 主界面可选择公式球（含固定步长展示）并开始游戏。
- [ ] 整局时长 ≤ 2 分钟（当前设计：阶乘球 50.3s / 三角阶乘球 36.3s / 正方阶乘球 30.5s）。
- [ ] 重力/下落速度集中可配置，重力球钩子预留且不启用。
- [ ] 后端下发关卡配置，改配置不改代码即可调难度；前端断网有兜底配置。
- [ ] `balance-calc.mjs` 19 条断言全绿；后端单测与应用测试全绿；前端物理自测误差 < 5%。
- [ ] Git 历史清晰（分支 + 规范提交 + 里程碑 tag），`target/` 未入库。
- [ ] README 能让新人三条命令跑起来。
