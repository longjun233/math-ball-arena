# 数学弹球闯关（Math Ball Arena）

自动演示型数学闯关小游戏。玩家只在开局选一颗「公式球」，之后全程无需操作：
小球在屏障上反复弹跳，每次碰撞公式升阶、伤害按公式爆炸增长；屏幕顶部一整排尖刺匀速下落，
就是可视化的时间限制。尖刺触球即失败，穿过一关的 3 道屏障落入底部安全区即过关。

- 共 **9 关**，血量全部是 10 的整数次幂，第 9 关第 3 道屏障锁定 **10³⁰⁰**
- 3 种公式球：阶乘球 `n!`(+2)、三角阶乘球 `T(n)!`(+1)、正方阶乘球 `(n²)!`(+1)
- **阶乘球是最弱球种，永远过不了第 8、9 关** —— 这不是数值巧合，是增长率的硬事实
- 后端 Java 17 + Spring Boot 3 下发关卡配置，前端原生 HTML5/Canvas，零构建链

---

## 快速开始

前置：**JDK 17+**、Maven 3.9+

```powershell
.\mvnw.ps1 test              # 跑后端单元测试
.\mvnw.ps1 spring-boot:run   # 启动，浏览器打开 http://localhost:8080
```

`mvnw.ps1` 做两件事：自动挑选一个 JDK 17+（本机 `JAVA_HOME` 可能指向 JDK 8），
以及把 Maven 本地仓库固定到项目内的 `.m2repo/`（避免写用户目录被沙箱拒绝）。

调试面板：`http://localhost:8080/?debug=1` —— 实时显示理论/实际耗时、时限余量、撞击计数。

## 玩法

```
选球 → 第1关 → (破碎3道屏障) → 第2关 → … → 第9关 → 通关界面
                  ↓尖刺触球
               失败界面
```

- 小球常态**只显示公式**（如 `34!`），碰撞瞬间才弹出当前伤害飘字
- 伤害 < 10⁶ 用千分位，≥ 10⁶ 用科学计数法（`4.79×10⁸`）
- 过关**不弹结算界面**，只播 0.6s 关卡号过场后小球回到顶部重新下落
- 结束界面（通关 / 失败）只有数据、**没有任何按钮**，点击空白处返回选球界面

## 数值设计

| 关 | 血量（三道屏障） | 尖刺速度 | 推荐球 |
|---|---|---|---|
| 1 | 10⁴ / 10¹² / 10²⁰ | 71.3 px/s | 阶乘球 |
| 2 | 10⁵ / 10¹³ / 10²¹ | 76.7 px/s | 阶乘球 |
| 3 | 10⁶ / 10¹⁴ / 10²² | 78.6 px/s | 阶乘球 |
| 4 | 10⁷ / 10¹⁵ / 10²³ | 82.4 px/s | 阶乘球 |
| 5 | 10⁸ / 10¹⁶ / 10²⁴ | 85.8 px/s | 阶乘球 |
| 6 | 10⁹ / 10¹⁷ / 10²⁵ | 89.9 px/s | 阶乘球 |
| 7 | 10¹⁰ / 10¹⁸ / 10²⁶ | 94.4 px/s | 阶乘球 |
| 8 | 10²⁰ / 10⁵⁰ / 10⁸⁰ | 99.2 px/s | 三角阶乘球 |
| 9 | 10⁸⁵ / 10¹⁹⁵ / **10³⁰⁰** | 100.6 px/s | 正方阶乘球 |

规律：同关内相邻屏障相差 8 个数量级；第 1~7 关之间每关整体上移 1 个数量级
（让阶乘球每关的撞击次数恒定在 10~12 击，从而让尖刺速度能逐关递增）。

门槛矩阵（真机逐帧模拟结果）：

| 关 | 阶乘球(+2) | 三角阶乘球(+1) | 正方阶乘球(+1) |
|---|---|---|---|
| 1~7 | 10~12 击 ✅ | 5 击 ✅ | 3~4 击 ✅ |
| 8 | 9 击 ❌ 超时 | 9 击 ✅ | 6 击 ✅ |
| 9 | 9 击 ❌ 超时 | 9 击 ❌ 超时 | 11 击 ✅ |

## 数值验证工具（改任何物理参数后必须全部重跑）

```powershell
node tools/calibrate.mjs         # 二分搜索每关临界尖刺速度，按目标余量反推速度（13 条断言）
node tools/physics-selftest.mjs  # 用真实 physics.js 逐帧模拟，验证门槛矩阵（13 条断言）
```

⚠️ **千万不要用解析公式估算限时**。尖刺的触发点是「小球在屏障 1 上弹跳到最高点时的球顶」，
而不是「尖刺走满画布」。小球会随关卡推进下落到更低的屏障，可用时间随之变长 —— 这个非线性关系
只能靠真机模拟得到。早期版本正是用均匀行程近似，导致第 6、7、9 关全部算错。

### 修改物理参数的标准流程

1. 改 `src/main/resources/application.yml` 的 `mathball.physics`
2. 同步 `src/main/resources/static/js/config.js` 的 `PHYSICS_DEFAULTS`
3. 跑 `node tools/calibrate.mjs`，把输出的 `spikeSpeed` 抄回 `config.js` 与 `levels.yml`
4. 跑 `node tools/physics-selftest.mjs`，13 条断言必须全绿

## ⚠️ 关于「重力球」

`js/traits.js` 里预留了 `gravity` 钩子（每次碰撞后 `gravityMul *= 1.06`），但 **v1 未启用**。

原因：重力 `g` 一旦变化，弹跳高度 `v0²/2g` 与弹跳周期 `2v0/g` 全部改变，
上表所有尖刺速度立刻失效。**启用任何改变 `g` 或 `v0` 的球种前，必须重跑上面的标定流程。**

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/levels` | 9 关配置 + 物理常量 + 过场配置 |
| GET | `/api/levels/{n}` | 单关配置 |
| GET | `/api/balls` | 公式球清单 |
| POST | `/api/runs` | 上报战报 |
| GET | `/api/runs/best` | 最佳成绩 |

血量以**十进制字符串**下发（`10^300` 会超出 JSON number 精度）。
每关还附带 `formulaCheck`，前端启动时用本地 BigInt 重算比对，防止前后端公式实现漂移。
